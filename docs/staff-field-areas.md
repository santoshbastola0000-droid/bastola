# Field areas, place names and weekly results

Stacked on staff-tracking lifecycle PR #251. Requires the companion backend staff field-policy PR; not a standalone deployed feature.

Admin Staff Tracking adds a Google Map circle selector and named-area checkboxes. The browser SDK loads only when the backend explicitly enables v2. A centre/radius circle is an administrative boundary, not an official neighbourhood boundary. Save assigns checked areas to future shifts. Staff can report a ROOM_ADDED, RENTAL_FIXED or OWNER_NO_ANSWER source-record ID for independent admin review. Weekly reporting defaults to the current Nepal Monday and counts VERIFIED reports only. Ranking explicitly prioritizes rental fixes and then room additions; unanswered owners do not count as poor performance. Claims are not automatically verified by the UI.

Google configuration: NEXT_PUBLIC_GOOGLE_MAPS_API_KEY must be referrer/API restricted. A private backend GOOGLE_MAPS_API_KEY and explicit GOOGLE_GEOCODING_ENABLED=true enable optional reverse geocoding. Assigned-area names work without reverse geocoding; unknown names remain unknown, not invented coordinates-as-address. Review Google attribution, API/billing, privacy and consent configuration before enabling. No provider credentials or actual staff GPS were tested here.

The backend's reviewed additive migration and STAFF_FIELD_POLICY_V2_ENABLED=true are required for assignment and payroll gating. A complete observed 10:00–17:00 Asia/Kathmandu window, maximum fifteen-minute GPS gap, definite in-area samples and final verification are required for automatic credit. Boundary uncertainty and missing evidence mean review, not proof of misconduct. Browser suspension/closed apps cannot guarantee continuous GPS. This UI does not implement native background tracking.

Remaining verification: apply the reviewed migration only to an isolated staging database after a verified backup; use designated staff/admin accounts; test Google Map rendering and named circles, profile switching, immutable active-session assignment, poor GPS, no assignment, all shift edges, weekly claim verification/duplicates and real PostgreSQL wallet concurrency. Verify actual source records before approving outcomes. Ledger workDate is the claim-report date; automatic attribution by underlying room/booking/call event time is not implemented. Do not describe these counts as complete historic or provider-verified totals. No live migrations, credits or deployment have been executed.
